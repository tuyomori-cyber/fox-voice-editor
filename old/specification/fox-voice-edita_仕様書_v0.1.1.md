# fox-voice-edita 仕様書 v0.1.1（構想・MVP）

作成日：2026-10-19  
改訂日：2026-10-19  
状態：実装前仕様案。v0.1から録音責務・通信構成を変更。

## 1. 概要

**fox-voice-edita** は、短い発話を文字起こしして独立したテキストブロックとして蓄積し、タッチ操作で並べ替え・挿入・削除・再利用する Firefox 拡張。音声だけで完成した一文を話す必要はない。音声で素材を作り、タッチで編集する「Voice CLI / 音声ブロックエディタ」を目指す。

初期用途は foxbook（Surface Pro 4 / Fedora / Cage + Firefox）のタッチオンリー環境で Codex への開発指示を作ること。ただし **Codex 連携自体は MVP に含めない**。汎用的な文章組み立てツールとして独立させる。

### 基本原則
- 音声＝テキスト断片の生成、タッチ＝断片の編集。
- 一回の録音で完成文を要求しない。単語、句、短文を歓迎する。
- 原文保持とは、認識結果を勝手に校正・要約・意味変更しないこと。過去版の恒久保存は意味しない。
- **Firefoxは録音しない。** Firefoxから録音開始・停止・キャンセルの指示を送り、Linux側がマイクを直接扱う。
- **音声データはFirefoxを経由しない。** Firefoxとローカル側の間で交換するのは制御メッセージ、状態、認識結果テキストのみ。
- 録音と保存だけで Codex や OS の任意コマンドを実行しない。
- foxbook control / The Session Tools / 仮想キーボードとは別拡張。

## 2. 対象環境
- 主対象：Surface Pro 4、Fedora、カスタマイズした Cage、デスクトップ版 Firefox、タッチのみで通常操作。
- 開発・検証：Xubuntu 24.04 + Firefox。SSHメンテナンスは許容。
- 音声認識：**whisper.cpp**。Xubuntuで日本語baseモデルの試験実績あり。Surface実機の速度・メモリは未検証。
- Firefox拡張：WebExtension（Manifest V3想定）。録音API（getUserMedia / MediaRecorder）は使用しない。
- マイク入力・音声ファイル形式変換・whisper.cpp実行はLinux側バックエンドの責務。

## 3. MVP 機能

### 3.1 録音と文字起こし
1. 拡張の専用編集画面に大きな録音操作ボタンを配置。
2. ボタン操作をNative Messaging経由でローカルバックエンドへ伝達する。
3. ローカルバックエンドがマイクから直接録音し、必要な形式へ変換してwhisper.cppで認識する。
4. 認識結果の**テキストだけ**を拡張へ返し、**1録音＝1テキストブロック**として末尾または指定位置へ追加する。
5. 認識失敗・キャンセル・空文字列の場合はブロックを自動追加しない。
6. 待機・録音中・認識中・完了・失敗・キャンセルの状態をUIへ表示する。
7. 押し続け方式とタップ開始・停止方式はSurface実機で決定する。録音時間上限を設ける（具体値は実機検証後）。

### 3.2 ブロック編集
- 各ブロックは独立したテキストを持ち、選択・削除・再録音（置換）できる。
- **再録音は認識成功後にのみ置換を確定**する。失敗・キャンセル時は元のブロックを保持する。
- タッチで順序を変更する。ドラッグか上下ボタンかは実機評価で決定。
- ブロック間と先頭・末尾に挿入ポイントを設け、録音・履歴再利用が可能。
- 文字単位の手動編集はMVP必須ではない。既存の仮想キーボード等を用いた編集は追加候補。
- 編集途中の内容はローカルに保存し、画面を閉じても復元できる。

### 3.3 履歴＝テンプレート
- 認識結果を**ブロックとして採用した時点**で履歴へ登録。失敗・キャンセル結果は登録しない。
- 履歴から選んだ文字列は通常ブロックとして挿入する。
- 最近使った項目を表示し、ピン留めした項目を固定テンプレートとして利用する。
- 例：「既存機能は維持」「まず現状を調査」「テストを実行」「ただし」「ではなく」「の」「を」。
- 履歴とテンプレートは同じデータモデルで管理する。
- 同一文字列は重複登録せず、再利用時に最終使用日時・使用回数を更新する方針。
- 履歴だけの削除を可能にする。履歴最大件数は未決。

### 3.4 ブロック間の挿入
- ブロック間の `＋` ボタンから接続詞・助詞・条件を表す定型句を挿入できる。
- 選択した定型句も通常ブロックとして扱う。
- 例：`Firefox` → `の` → `最小化ボタン` → `を` → `1.5倍にする` → `ただし` → `位置は変更しない`。
- 意味タグ付けはMVP対象外。

### 3.5 出力
- ブロックを表示順に連結してプレビューする。
- クリップボードにコピーし、Codex等へ手動貼り付けできる。
- **連結規則は未確定**。助詞・単語を細かく組み合わせる用途があるため、改行固定にはしない。区切りなし・空白・改行の扱いは実例と実機で決定する。
- JSON相当の構造で内部保存。JSONファイルのエクスポート／インポートは未決。
- Codexへの自動送信・AI整形・コード編集は行わない。

## 4. UI イメージ（概念）

```text
fox-voice-edita

[🎤 録音する]     [状態：待機]

[ Firefox                ] [削除] [再録音]
             [+ 挿入]
[ の                     ] [削除]
             [+ 挿入]
[ 最小化ボタン           ] [削除] [再録音]
             [+ 挿入]
[ を                     ] [削除]
             [+ 挿入]
[ 1.5倍にする            ] [削除] [再録音]

[履歴] [ピン留め]       [プレビュー] [コピー]
```

- タッチしやすいボタン・十分な間隔を優先。縦横回転・Firefox UIスケールに配慮。
- ツールバーポップアップでは狭いため、**拡張専用タブ**を第一候補とする。
- 誤タップ防止、長文の折り返し、スクロール位置保持を考慮。

## 5. アーキテクチャ（v0.1.1で変更）

```text
Firefox WebExtension
  ├─ 編集ページ（録音操作・ブロック・履歴）
  ├─ ローカル保存（browser.storage.local / IndexedDB候補）
  └─ Native Messaging クライアント
          │
          │ JSON：start / stop / cancel / status / 認識結果
          │ ※音声バイナリは送らない
          ▼
Native Host（ローカル制御）
          │
          ▼
Linux側録音・認識バックエンド
  ├─ マイク入力（OSの音声デバイス）
  ├─ 一時音声データ／必要な形式変換
  └─ whisper.cpp
          │
          └─ 認識テキスト → Native Host → Firefox
```

### 5.1 責務の分離
- **Firefox：** 録音操作の指示、状態表示、認識テキストの受信、ブロック編集、履歴、コピー。
- **Native Host：** 許可された固定アクションの受付・検証、録音バックエンドとの通信、結果通知。
- **Linuxバックエンド：** マイク録音、停止・キャンセル、音声形式変換、whisper.cpp実行、後片付け。
- Firefox側にマイクアクセス権限は不要。音声ファイルをBase64等で拡張へ渡す設計は採用しない。

### 5.2 通信とプロセス寿命
- FirefoxとNative Hostの通信は**Native Messagingを第一候補**とする。localhost HTTPを第一候補とはしない。
- `start_recording` / `stop_recording` / `cancel_recording` / `get_status` 等の固定アクションを想定。具体的なJSON契約は試作時に決定。
- `sendNativeMessage()`は呼び出しごとにHostが起動されるため、録音状態をHostの短命プロセス内だけに保持しない。
- 第一検討案は`connectNative()`で持続接続し、録音開始から認識結果受信までHostを維持する構成。
- 別案としてNative Hostから独立したローカル録音・認識プロセスを管理する方式も検証可能。
- 拡張タブを閉じた場合・Native Messaging接続断・Firefox終了時に録音が取り残されないよう、停止・終了処理を設計する。
- モデルを毎回ロードする方式と常駐させる方式はSurface実測により選択。**常駐は確定事項ではない**。
- 同時録音・認識は原則1件。録音・認識中の競合操作を制限し、失敗時にUIを復帰させる。
- Firefoxとwhisper.cppの間に音声データ転送経路を作らない。

## 6. データモデル案

```json
{
  "schemaVersion": 1,
  "document": {
    "blocks": [
      {"id": "b1", "text": "Firefox", "origin": "voice"},
      {"id": "b2", "text": "の", "origin": "history"},
      {"id": "b3", "text": "最小化ボタンを大きく", "origin": "voice"}
    ]
  },
  "history": [
    {"id": "h1", "text": "既存機能は維持", "pinned": true, "lastUsedAt": null, "useCount": 0}
  ]
}
```

- ブロックIDは一意。履歴からの挿入時も新しいIDを発行。
- `origin`は参考情報。編集上は共通。
- 順序は`blocks`配列順。テンプレートは`history.pinned`で表す。
- 保存API、時刻、スキーマ移行は実装時に確定。
- 原音声は恒久保存しない方針。録音・認識終了後の一時データは破棄する。

## 7. セキュリティ・プライバシー
- マイク利用はユーザーの明示操作時のみ。録音状態をUIに表示する。
- 録音・認識はLinuxローカルで完結し、クラウド送信しない。
- Native Hostは固定アクションだけを許可し、任意コマンド文字列や任意ファイルパスを実行引数として受け付けない。
- ローカル録音・認識プロセスの停止と一時ファイルの消去を保証する。
- Firefox終了・Host異常終了時に録音し続けないための終了処理を検証する。
- 保存データ・履歴の削除UIを提供し、自動保存失敗を通知する。

## 8. MVP 受け入れ条件
1. 物理キーボードなしで拡張専用画面を開ける。
2. FirefoxのマイクAPIを使わず、Linux側で録音して日本語認識結果をテキストで受け取れる。
3. 複数の短い発話を独立したブロックとして蓄積できる。
4. 再録音失敗・キャンセル時に既存ブロックが保持される。
5. タッチだけで削除・並べ替え・途中挿入ができる。
6. `＋` から履歴・接続詞を挿入でき、ピン留めして再利用できる。
7. 編集内容が画面再表示後も復元される。
8. プレビュー・コピーができ、SurfaceのCodex入力欄へタッチ操作だけで貼り付けられる。
9. Surfaceでtiny/base等の認識時間・メモリ使用量・モデル読み込み時間を測定し、実用性を判断できる。
10. 録音と編集によってCodexや任意のOSコマンドが実行されない。
11. 録音中の接続断・キャンセル・画面終了で録音プロセスが取り残されない。

## 9. MVP の対象外（将来構想）
- Codex App Server / CLIへの直接送信。
- 意図確認エージェントと実装エージェントの分離。
- AIによる文章の自動整形・要約・誤認識補正。
- コード差分レビュー、Git操作、Firefoxアドオンの自動リロード。
- 音声による編集コマンド、音声以外の入力デバイス対応。
- 高度な履歴推薦、使用頻度ランキング、意味タグ付き接続関係。

## 10. 未決事項と最初の検証順

**未決事項：** 録音ボタン操作、Surfaceでのtiny/base性能、モデル常駐の要否、Native Hostと録音プロセスの寿命管理、音声録音方式・一時形式、保存API、ブロック移動UI、履歴最大件数、コピー連結規則、認識言語固定と自動判定の比較。

**推奨検証順：**
1. Xubuntu上でFirefoxを介さず、Linuxのマイク録音→whisper.cpp→日本語テキスト出力をCLIで確認する。
2. Firefox拡張からNative Messagingで開始・停止を指示し、**音声データをFirefoxに通さず**認識文字列を1件返す。
3. モデル読み込み・認識時間・メモリ・接続断時の後片付けを測定する。
4. 複数ブロックの表示・保存・再録音・削除・並べ替え・途中挿入を実装する。
5. 履歴・ピン留め・`＋`挿入を実装する。
6. Surface / Cage / タッチのみで録音からCodex入力欄への貼り付けまで確認する。

## 11. 名前について

プロジェクト名はユーザー提案の **`fox-voice-edita`** を採用（仮決定）。`edita` は一般的な英語の `editor` とは異なる独自表記だが、プロジェクト名として使用可能。GitHubリポジトリ名・拡張ID・表示名の最終決定は別途行う。

## 12. v0.1 → v0.1.1 変更履歴
- Firefox内録音（getUserMedia / MediaRecorder）を廃止し、Linux側マイク録音へ変更。
- Firefox↔バックエンド間の音声転送・Base64・ストリーミング検討を削除。
- Native Messagingを録音制御・状態・認識テキスト用の第一候補に明確化。
- Native Hostの接続寿命、録音プロセス終了、モデル読み込みの論点を追加。
- 再録音失敗時の原文保持、履歴登録時点、競合制御、実機貼り付け検証を明確化。
- コピーの連結規則は、短い助詞ブロックの用途を考慮して未決のまま維持。
