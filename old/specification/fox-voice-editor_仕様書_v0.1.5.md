# fox-voice-editor 仕様書 v0.1.5（試作・MVP）

作成日：2026-10-19　改訂日：2026-10-19  
状態：v0.1.4のマイク補正を接続時の必須確認と手動再確認へ変更。新UIおよび補正機能の実機検証は未実施。

## 1. 概要

**fox-voice-editor** は、短い発話を文字起こしして独立したテキストブロックとして蓄積し、タッチ操作で並べ替え・挿入・削除・再利用するFirefox拡張。音声だけで完成した一文を話す必要はない。音声で素材を作り、タッチで編集する「Voice CLI / 音声ブロックエディタ」を目指す。

初期用途はfoxbook（Surface Pro 4 / Fedora / Cage + Firefox）のタッチオンリー環境でCodexへの開発指示を作ること。ただし**Codex連携自体はMVPに含めない**。汎用的な文章組み立てツールとして独立させる。

### 基本原則

- 音声＝テキスト断片の生成、タッチ＝断片の編集。
- 一回の録音で完成文を要求しない。単語、句、短文を歓迎する。
- 原文保持とは、認識結果を勝手に校正・要約・意味変更しないこと。過去版の恒久保存は意味しない。
- **Firefoxは録音しない。** Firefoxから録音開始・停止・キャンセルの指示を送り、Linux側がマイクを直接扱う。
- **音声データはFirefoxを経由しない。** Firefoxとローカル側の間で交換するのは制御メッセージ、状態、認識結果テキストのみ。
- 録音と保存だけでCodexやOSの任意コマンドを実行しない。
- foxbook control / The Session Tools / 仮想キーボードとは別拡張。
- **端末固有のマイク補正は明示的に有効化された環境だけで行う。** OSの音声管理サービスやグローバルな設定は変更しない。

## 2. 対象環境

- 主対象：Surface Pro 4、Fedora、カスタマイズしたCage、デスクトップ版Firefox、タッチのみで通常操作。
- 開発・検証：Xubuntu 24.04 + Firefox。SSHメンテナンスは許容。
- 音声認識：**whisper.cpp**。Xubuntuで日本語baseモデルの試験実績あり。Surfaceでも実行を確認したが、認識品質・処理時間の定量評価は継続中。
- Firefox拡張：WebExtension（Manifest V3想定）。録音API（getUserMedia / MediaRecorder）は使用しない。
- マイク入力・音声ファイル形式変換・whisper.cpp実行はLinux側バックエンドの責務。
- Surface Pro 4実機の内蔵マイク（HDA Intel PCH / Realtek ALC298）では、ALSAの`Internal Mic Boost`が+30dBのとき録音に強いノイズが入り、0dBで改善することを確認済み。WirePlumber起動・再起動時に+30dBへ戻る現象も再現済み。

## 3. MVP機能

### 3.1 録音と文字起こし

1. 拡張の専用編集画面に大きな録音操作ボタンを配置。
2. ボタン操作をNative Messaging経由でローカルバックエンドへ伝達する。
3. ローカルバックエンドがマイクから直接録音し、必要な形式へ変換してwhisper.cppで認識する。
4. Native Hostが録音ごとに一意の`recordingId`を発行する。認識結果の**テキストだけ**を拡張へ返し、認識成功時に**1録音＝1テキストブロック**として末尾または指定位置へ自動追加する。
5. 認識失敗・キャンセル・空文字列の場合はブロックを自動追加しない。
6. 待機・録音中・認識中・完了・失敗・キャンセルの状態をUIへ表示する。
7. 録音開始・停止は単一のトグルボタンとする。開始・停止の応答待ちは無効化し、エラー時はNative Hostへ状態を再照会する。現行の録音時間上限は暫定30秒とし、Surface実機で見直す。
8. 録音停止から結果表示までの仮目標は3秒以内、5秒以内を実用範囲とする。Surfaceでの実測後に再評価する。
9. 編集画面がNative Hostへ接続した際に`prepare_microphone`を要求し、成功応答まで録音を無効にする。必要に応じて画面の「マイクを再確認」から再実行できる。録音ごとの自動確認は行わない。詳細は§3.6。

### 3.2 ブロック編集

- 各ブロックは文字列だけを角丸の四角に表示する。横に並べ、横幅が足りなくなったら次の行へ折り返す。「ブロック」という見出しは表示しない。
- ブロックを短くタップすると「前へ挿入」「後ろへ挿入」「再録音」「削除」の操作メニューを開く。
- **再録音は認識成功後にのみ置換を確定**する。失敗・キャンセル時は元のブロックを保持する。
- タッチのドラッグ中に表示順を動かし、指を離した順序を保存する。上下移動ボタンは表示しない。
- 履歴を選択中に「前へ挿入」「後ろへ挿入」を押すと、その語句を対象ブロックの前後へ入れる。履歴未選択なら指定位置への録音を開始する。末尾への録音は主ボタンから開始できる。
- 文字単位の手動編集はMVP必須ではない。既存の仮想キーボード等を用いた編集は追加候補。
- 編集途中の内容はローカルに保存し、画面を閉じても復元できる。

### 3.3 履歴＝テンプレート

- 認識成功時にブロックへ自動追加し、同時に履歴へ登録する。確認画面は設けず、失敗・キャンセル・空文字列は登録しない。
- 履歴の文字列をタップすると選択状態にする。同じ項目を再タップすると解除する。履歴画面から直接挿入するボタンは設けない。
- 各履歴の「…」をタップすると、ピン留め／解除と履歴からの削除を表示する。
- ピン留め項目を先に、通常履歴を新しい順に表示する。通常履歴は30件ずつ追加表示する。
- 例：「既存機能は維持」「まず現状を調査」「テストを実行」「ただし」「ではなく」「の」「を」。
- 履歴とテンプレートは同じデータモデルで管理する。
- 同一文字列は重複登録せず、再利用時に最終使用日時・使用回数を更新する方針。
- 履歴だけの削除を可能にする。履歴の上限は暫定500件。上限を超えたら古い通常履歴から削除し、ピン留め項目は自動削除しない。ピン留め項目だけで500件を超える場合は例外的に上限超過を許す。履歴削除は既存ブロックへ影響しない。

### 3.4 ブロック間の挿入

- 履歴で選んだ接続詞・助詞・条件句を、対象ブロックの「前へ挿入」「後ろへ挿入」から追加できる。
- 選択した定型句も通常ブロックとして扱う。
- 助詞・接続詞は短い発話の認識結果に依存せず、履歴・テンプレートから挿入する運用を想定する。短い発話の認識品質は実機で測定する。
- 例：`Firefox` → `の` → `最小化ボタン` → `を` → `1.5倍にする` → `ただし` → `位置は変更しない`。
- 意味タグ付けはMVP対象外。

### 3.5 出力

- ブロックを表示順に**区切りなし**で連結してプレビューする。
- クリップボードにコピーし、Codex等へ手動貼り付けできる。
- プレビューの文字列とクリップボードへコピーする文字列は完全一致させる。ブロック間に空白や改行は自動挿入しない。
- JSON相当の構造で内部保存。JSONファイルのエクスポート／インポートは未決。
- Codexへの自動送信・AI整形・コード編集は行わない。

### 3.6 端末固有のマイクブースト補正【v0.1.4追加】

**目的：** Surface Pro 4の内蔵マイクで発生する過大なアナログブーストによる録音ノイズを、音声入力を使用するfox-voice-editor側で局所的に補正する。ALSA・WirePlumberの起動設定、音声プロファイル、他の音声経路は変更しない。

**起動条件とタイミング**

1. Firefoxの拡張専用編集画面がNative Hostへ接続した際、固定アクション`prepare_microphone`を要求する。成功応答を受けるまで録音操作を無効にする。
2. 既存タブを再度アクティブにするだけでは自動再確認しない。異常を感じた場合は「マイクを再確認」ボタンから同じアクションを手動で実行する。確認中は録音操作を無効にする。録音開始のたびには確認しない。
3. **補正対象として明示設定された環境だけでミキサーを読み書きする。** Xubuntuなど未設定の環境では`skipped`として録音を許可する。
4. 補正はマイク使用のための事前準備であり、それ自体で録音を開始しない。ユーザーの録音操作がなければ音声を収集しない。

**Native Host側の固定処理**

- アクション名：`prepare_microphone`。Firefox側はコマンド文字列、カード名、ミキサー名、設定値を送信しない。
- Surface向け対象はコード内で`card = PCH`、`control = Internal Mic Boost`、`target = 0`に固定する。端末ローカルの設定には有効・無効だけを保持し、Native Messaging要求からは変更できない。
- まず固定引数で`/usr/bin/amixer -c PCH sget 'Internal Mic Boost'`を実行して現在値を取得する。**0dB相当の整数値0であれば変更しない。** 左右いずれかが0を超える場合にのみ、固定引数で`/usr/bin/amixer -c PCH sset 'Internal Mic Boost' 0`を実行する。
- `amixer`出力の解析は左右のチャンネル値を厳密に扱い、解析不能・コントロール不在・コマンド失敗の場合は成功扱いにしない。変更後は再取得し、左右とも0になったことを検証する。`shell=True`や自由入力のコマンド実行は使わない。
- 処理は冪等（繰り返し呼び出しても0なら変更しない）とする。タイムアウトを設け、長時間待機しない。
- 応答は`event: microphone_prepared`とし、`status`は無効時`skipped`、既に0なら`unchanged`、変更して0になったら`adjusted`、失敗時`error`とする。失敗時には`code`と`message`を付ける。
- 接続時または手動再確認時に失敗した場合はUIへエラーを表示し、録音を無効のままにする。再確認に成功すると録音を再び有効にする。最後の確認時刻を表示する。補正無効の環境では`skipped`応答を成功として扱う。

**ローカル設定**

```json
{
  "boost_fix": true
}
```

- 設定ファイルは`~/.config/fox-voice-editor/microphone.json`。ファイルがなければ`boost_fix: false`として扱い、Surface実機でのみ`{"boost_fix": true}`を明示設定する。
- ほかの音声デバイスや汎用的なミキサー変更機能へ拡張しない。対象外のカード・コントロールへのフォールバックも行わない。
- マイク補正は録音前の限定的な固定アクションであり、§1および§7の「任意コマンド実行禁止」と矛盾しない。

- 編集と履歴を横並びの2ペインで表示する。狭い画面では縦に並ぶ。タッチしやすいボタン・十分な間隔を優先する。

## 5. アーキテクチャ

```text
Firefox WebExtension
  ├─ 編集ページ（録音操作・ブロック編集／履歴の2ペイン）
  ├─ ローカル保存（browser.storage.local）
  └─ Native Messaging クライアント
          │
          │ JSON：prepare_microphone / start / stop / cancel / status
          │       recordingId / 認識結果（音声バイナリは送らない）
          ▼
Native Host（ローカル制御）
  ├─ 許可された固定アクションの検証
  ├─ [補正有効時のみ] amixerによるInternal Mic Boost確認・補正
  └─ 録音プロセス管理
          │
          ▼
Linux側録音・認識バックエンド
  ├─ マイク入力（OSの音声デバイス）
  ├─ 一時音声データ／必要な形式変換
  └─ whisper.cpp
          │
          └─ 認識テキスト → Native Host → Firefox
```

### 5.1 責務の分離

- **Firefox：** 録音操作の指示、マイク準備アクションの要求と結果表示、状態表示、認識テキストの受信、ブロック編集、履歴、コピー。
- **Native Host：** 許可された固定アクションの受付・検証、マイクブースト補正（明示有効時のみ）、録音バックエンドとの通信、結果通知。
- **Linuxバックエンド：** マイク録音、停止・キャンセル、音声形式変換、whisper.cpp実行、後片付け。
- Firefox側にマイクアクセス権限は不要。音声ファイルをBase64等で拡張へ渡す設計は採用しない。

### 5.2 通信とプロセス寿命

- FirefoxとNative Hostの通信は**Native Messagingを第一候補**とする。localhost HTTPを第一候補とはしない。
- 現行試作は`prepare_microphone` / `start_recording` / `stop_recording` / `cancel_recording` / `get_status`の固定アクションを使う。`prepare_microphone`は接続時と手動操作時に呼び出す。Native Hostが録音ごとに一意の`recordingId`を発行し、応答と結果を対応付ける。正式なJSON契約は実機検証後に確定する。
- `sendNativeMessage()`は呼び出しごとにHostが起動されるため、録音状態をHostの短命プロセス内だけに保持しない。
- 第一候補は`connectNative()`で持続接続し、録音開始から認識結果受信までHostを維持する構成。Native Hostが録音プロセスの管理責任を持つ。
- Native Hostは録音IDと録音状態を管理する。ブロックID・挿入位置・置換対象と録音IDの対応付けはFirefox側で管理し、Native HostへブロックIDや挿入位置を渡さない。
- 拡張タブを閉じた場合・Native Messaging接続断・Firefox終了・Host異常終了時に録音プロセスが取り残されないよう、停止・終了処理を設計する。
- モデルを毎回ロードする方式と常駐させる方式はSurface実測により選択。**常駐は確定事項ではない**。
- 同時録音・認識は原則1件。録音・認識中の競合操作を制限し、失敗時にUIを復帰させる。
- 停止要求済みの状態は`stopping`として照会可能にする。エラー時は状態を再照会し、録音先が特定できない認識結果はブロックへ誤挿入しない。
- Firefoxとwhisper.cppの間に音声データ転送経路を作らない。
- マイク入力方式・一時音声形式はLinux側のCLI録音試験で決め、XubuntuとSurfaceの両環境で検証する。
- `prepare_microphone`は録音とは独立した固定アクション。接続ごとに成功するまで録音を拒否し、確認中・録音中の二重実行を避ける。接続後にWirePlumberが値を戻しても自動検知はしない。

## 6. データモデル案

```json
{
  "schemaVersion": 1,
  "document": {
    "blocks": [
      {"id": "b1", "text": "Firefox", "origin": "voice"},
      {"id": "b2", "text": "の", "origin": "history"},
      {"id": "b3", "text": "最小化ボタンを大きく", "origin": "voice"}
    ]
  },
  "history": [
    {"id": "h1", "text": "既存機能は維持", "pinned": true, "lastUsedAt": null, "useCount": 0}
  ]
}
```

- ブロックIDは一意。履歴からの挿入時も新しいIDを発行。
- `origin`は参考情報。編集上は共通。
- 順序は`blocks`配列順。テンプレートは`history.pinned`で表す。
- 現行試作の保存APIは`browser.storage.local`、保存スキーマは`schemaVersion: 1`。スキーマ移行方針は未決。
- 原音声は恒久保存しない方針。録音・認識終了後の一時データは破棄する。
- 録音中の`recordingId`と挿入位置または置換対象との対応付けはFirefox側の実行時状態として管理する。接続が切れた場合、Native Hostは録音プロセスを終了する。対応先を特定できない結果は追加しない。
- マイクブースト補正の有効化設定は端末ローカルのNative Host側で管理し、文書・履歴の保存スキーマには含めない。

## 7. セキュリティ・プライバシー

- マイク利用はユーザーの明示操作時のみ。録音状態をUIに表示する。編集画面表示時のマイクブースト確認・補正は録音を伴わない。
- 録音・認識はLinuxローカルで完結し、クラウド送信しない。
- Native Hostは固定アクションだけを許可し、任意コマンド文字列や任意ファイルパスを実行引数として受け付けない。
- `prepare_microphone`ではローカルに事前設定されたカード・コントロールだけを対象とし、固定の`amixer`引数を使用する。対象が存在しない・解析できない場合は失敗として扱い、他のミキサーを推測して変更しない。
- ローカル録音・認識プロセスの停止と一時ファイルの消去を保証する。
- Firefox終了・接続断・Host異常終了時に録音し続けないための終了処理を検証する。
- 保存データ・履歴の削除UIを提供し、自動保存失敗を通知する。

## 8. MVP受け入れ条件

1. 物理キーボードなしで拡張専用画面を開ける。
2. FirefoxのマイクAPIを使わず、Linux側で録音して日本語認識結果をテキストで受け取れる。
3. 録音ごとの`recordingId`で応答を対応付け、Native HostはブロックIDや挿入位置を管理しない。
4. 複数の短い発話を独立したブロックとして蓄積できる。認識成功時はブロックと履歴に自動追加される。
5. 再録音失敗・キャンセル時に既存ブロックが保持される。
6. タッチだけでブロックの操作メニューを開き、削除・ドラッグ並べ替え・前後挿入ができる。
7. 履歴を選択してブロックの前後へ挿入でき、「…」からピン留めや履歴削除ができる。履歴削除は既存ブロックに影響しない。
8. 編集内容が画面再表示後も復元され、既存エディタタブがあれば新規作成せずそのタブをアクティブにする。
9. ブロックを区切りなしで連結し、プレビューと同一の文字列をコピーしてSurfaceのCodex入力欄へタッチ操作だけで貼り付けられる。
10. Surfaceでtiny/base等の認識時間・メモリ使用量・モデル読み込み時間を測定し、停止から結果表示まで3秒以内を仮目標、5秒以内を実用範囲として再評価できる。
11. XubuntuとSurfaceでLinux側のCLI録音を確認できる。
12. 録音と編集によってCodexや任意のOSコマンドが実行されない。許可された固定マイク補正アクションのみ例外として実行可能。
13. 録音中の接続断・キャンセル・画面終了・Host異常終了で録音プロセスが取り残されない。
14. 補正を明示有効化したSurfaceでは、Native Host接続時と手動再確認時に`Internal Mic Boost`を確認し、左右が0なら変更せず、正の値なら0へ補正して再確認できる。録音のたびには確認しない。
15. 補正無効のXubuntu等ではミキサーへの読み書きを行わず録音できる。対象コントロール不在・取得失敗・設定失敗を報告し、確認が成功するまで録音を開始できない。
16. WirePlumberの再起動後に+30dBへ戻った場合、手動再確認で0dBへ戻せる。確認後に再び値が変化した場合は自動検知しないことをUIで分かるようにし、スピーカー再生や他の音声設定に意図しない変更がないことを確認する。

## 10. 現状と残る検証

- XubuntuではCLIでのマイク録音・変換・日本語認識と、Firefox画面での認識結果表示を確認済み。現行試作はNative Host、保存、ブロック編集、履歴、プレビュー、コピーまで実装済み。
- 新しい2ペインUIはFirefoxとSurfaceで未確認。録音ボタン、状態表示、ブロックのドラッグ、短いタップと操作メニュー、履歴選択と前後挿入、保存・復元、コピーを実機で確認する。
- タブ終了・接続断・Host異常終了時の録音プロセス終了を実機でも確認する。Host単体の擬似プロセス試験は成功済み。
- Surfaceでwhisper.cppを実行し、録音ノイズと文字起こし精度の問題を確認。ALSA `Internal Mic Boost`を+30dBから0dBへ変更すると、録音ノイズが大幅に改善することを確認済み。**ブースト補正後のfox-voice-editorでの認識品質・時間は未評価**。
- ALSA状態ファイルには0が保存されるが、WirePlumberの起動・再起動で+30dBに戻ることを確認済み。ログイン時のoneshotサービス（3秒待機を含む）では維持できなかったため、OS起動時補正方式は採用しない。
- `prepare_microphone`は接続時・手動再確認で実装済み。Surface実機での確認とUI操作の検証が必要。
- Surfaceでtiny/baseの認識品質、停止から結果表示までの時間、モデル読み込み時間、メモリを測る。毎回読み込みとモデル常駐の選択はその後に行う。
- 録音時間上限30秒、音声入力方式、正式なJSON契約、拡張ID、保存スキーマ移行、認識言語固定の扱いは実機結果を見て確定する。
- 履歴未選択時の前後挿入は現行試作では指定位置への録音としている。タッチ操作の分かりやすさを実機で確認する。

## 12. v0.1 → v0.1.1 変更履歴

- Firefox内録音（getUserMedia / MediaRecorder）を廃止し、Linux側マイク録音へ変更。
- Firefox↔バックエンド間の音声転送・Base64・ストリーミング検討を削除。
- Native Messagingを録音制御・状態・認識テキスト用の第一候補に明確化。
- Native Hostの接続寿命、録音プロセス終了、モデル読み込みの論点を追加。
- 再録音失敗時の原文保持、履歴登録時点、競合制御、実機貼り付け検証を明確化。
- コピーの連結規則は、短い助詞ブロックの用途を考慮して未決のまま維持。

## 13. v0.1.1 → v0.1.2 変更履歴

- `connectNative()`による持続接続を第一候補とし、Native Hostが録音プロセスを管理する方針を明確化。
- 録音ごとに`recordingId`を発行し、ブロックID・挿入位置はFirefox側で管理する方針を追加。
- 短い発話の実機評価、助詞・接続詞のテンプレート利用、認識時間の仮目標を追加。
- XubuntuとSurfaceのCLI録音試験でマイク入力方式を決める方針を追加。
- 認識成功時のブロック・履歴への自動追加と、確認画面を設けない方針を確定。
- コピー時の区切りなし連結と、プレビュー・コピーの完全一致を確定。
- エディタの単一タブ方式、履歴上限の暫定500件と削除規則を追加。
- 正式名称を`fox-voice-editor`に統一。

## 14. v0.1.2 → v0.1.3 変更履歴

- 録音開始・停止を単一ボタンにし、Hostとの状態再同期と停止要求済み状態を反映。
- 編集と履歴を横並びの2ペインにし、ブロック見出しを削除。
- 文字だけの角丸ブロック、横並びと折り返し、タッチドラッグによる並べ替え、短いタップの操作メニューへ変更。

## 15. v0.1.3 → v0.1.4 変更履歴

- Surface Pro 4で`Internal Mic Boost` +30dBによる録音ノイズを確認し、0dBで改善した実測結果を反映。
- WirePlumberの起動・再起動でブーストが+30dBへ戻るため、OS起動時サービスではなく、fox-voice-editorのNative Hostで局所的に補正する方針を採用。

## 16. v0.1.4 → v0.1.5 変更履歴

- Native Hostの端末ローカル設定は有効・無効だけを保持し、対象カード・制御・値は固定。
- WirePlumber再起動後の値の変化は自動検知しない制約を明記。
